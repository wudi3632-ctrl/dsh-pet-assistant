# DSH Pet 实时语音、Agent 与原创动画设计

日期：2026-11-17

## 目标

保留 DeepSeek Harness 作为唯一任务与会话中枢，把桌宠收敛为语音入口、状态演出和结果汇报界面。解决当前链路重复收音、响应割裂、LLM 首次反馈慢、复杂 Windows 任务可靠性不足的问题，并用远程 ComfyUI 的 MiniMax H3 逐步替换上游角色动画。

## 职责边界

### 桌宠端

- 常驻关键词唤醒、VAD、流式 ASR 与局部字幕。
- 把一条最终识别结果以唯一 `turnId` 提交给 DSH 指定会话。
- 消费 DSH 的结构化事件，显示气泡、任务卡片、确认状态和动作。
- 把 DSH 的流式回复按短句送入 Qwen TTS，并汇报最终结果。
- 不负责理解任务、规划 Windows 操作、选择工具或判断任务完成。

### DeepSeek Harness

- 持有会话、上下文、记忆和模型选择。
- 使用 GLM-5.3-Flash，推理强度明确设为 `low`。
- 负责意图理解、任务拆解、工具调用、权限确认、重试和结果验证。
- 通过 Windows 工具层执行操作，并向桌宠发布真实状态事件。
- 普通聊天和任务执行都进入 DSH 会话，不在桌宠中保留第二套 Agent。

## 事件协议

桌宠向 DSH 发送：

- `voice.partial`：局部识别，仅用于显示。
- `voice.final`：最终识别文本、`turnId`、会话标识和时间戳。
- `voice.cancel`：用户通过唤醒词打断当前 TTS 或回合。

DSH 向桌宠发布：

- `turn.accepted`
- `turn.thinking`
- `tool.started`
- `tool.progress`
- `approval.required`
- `assistant.delta`
- `turn.completed`
- `turn.failed`

同一 `turnId` 只能创建一个用户回合。桌宠不能根据定时器伪造 thinking、executing 或 completed。

## 实时语音状态机

状态顺序为：休眠 → 唤醒 → 倾听 → ASR 定稿 → DSH 接收 → 对话或执行 → TTS/结果汇报 → 回声冷却 → 连续会话或休眠。

- 默认连续会话窗口为 30 秒，并恢复读取 `voiceWakeActiveMs`，不再硬编码。
- TTS 播放期间关闭普通 VAD/ASR，只保留关键词检测。
- 播放中检测到配置的唤醒词时，停止 TTS、排空音频尾巴并开始新一轮倾听。
- TTS 自然结束后等待约 350 ms，再开放普通 VAD/ASR。
- ASR partial 只显示，不提交任务；final 只提交一次。
- 每次只有一个有效输入回合和一个有效播放队列。取消时同时清理 ASR、LLM 文本队列和 TTS 队列。
- UU 虚拟输入和实体麦克风使用不同 VAD 配置；虚拟输入关闭浏览器 AGC，并使用更严格的起音阈值。

## 流式响应

- DSH 接收用户消息后立即发布 `turn.accepted`，桌宠在 150 ms 目标内显示反馈。
- 普通回复通过 `assistant.delta` 增量显示。
- 桌宠对增量文本做中文句界检测，第一条完整短句立即送入 Qwen TTS；后续句子边生成边排队。
- 任务执行不朗读工具日志，只播报简短接收语、确认问题和最终结果。
- TTS 服务常驻并预热模型；缓存固定确认语与高频回复。

## Windows Agent 与权限

工具选择顺序：Win32/应用恢复 → Windows UI Automation → 浏览器 DOM/可访问性 → GLM 视觉定位 → 坐标输入兜底。每个修改动作后必须通过窗口状态、可访问性树、页面状态或截图进行验证。

- 读取、打开、切换、浏览和滚动自动执行。
- 用户明确要求的本地输入、文档编辑和保存自动执行。
- 发消息、公开发布、删除、安装、管理员权限和付款在最终动作前确认。
- 桌宠只渲染 DSH 的 `approval.required`，不维护独立权限规则。

## 现有代码迁移

- 从 `runtime/electron-helper/voice-wake.js` 移除 `windowsIntent`、Windows JSON 规划循环和直接执行职责。
- 将关键词、VAD、ASR、回声门禁和回合去重拆成独立模块，保留 Helper 作为音频与 UI 宿主。
- 在 DSH 插件宿主侧增加语音回合桥接和事件流，不另建第二份会话存储。
- 迁移期间保留现有确定性快捷动作作为 DSH 工具实现，而不是桌宠内部旁路。

## 原创动画管线

先制作不依赖上游角色画面的原创角色设定表，再把同一参考图交给远程 ComfyUI 的 MiniMax H3 图生视频工作流。远程只负责生成，仓库只保存公开许可允许的工作流模板和最终资产。

第一批动作：待机呼吸、唤醒回应、侧耳倾听、思考、说话、拖鼠标奔跑、执行操作、等待确认、成功庆祝、失败沮丧。

处理流程：参考图与固定提示词 → MiniMax H3 图生视频 → 背景移除 → 动作裁切和循环修复 → 统一尺寸、方向、脚底锚点和帧率 → VP9 Alpha WebM → 状态映射。

DSH 只发送 `listening`、`thinking`、`executing`、`waiting`、`success`、`error` 等语义状态。动画文件名由皮肤映射层决定。新动作通过身份一致性、透明边缘、脚底漂移、循环接缝和体积检查后才替换旧资源；不合格时继续使用旧动作。

## 性能目标

| 阶段 | 目标 |
|---|---:|
| 唤醒反馈 | ≤ 300 ms |
| VAD 收口 | 350–500 ms |
| ASR final | 收口后 ≤ 300 ms |
| DSH 接收反馈 | ≤ 150 ms |
| 普通对话首个文本 | ≤ 1.2 s |
| 第一段 TTS 首音 | 首句后 ≤ 700 ms |
| 任务接收反馈 | 指令结束后 ≤ 800 ms |
| 唤醒词打断 TTS | ≤ 500 ms |

## 验收

- 50 次唤醒与连续对话无重复提交。
- 30 次 TTS 播放不被识别为新指令。
- UU 虚拟输入和实体麦克风分别通过测试。
- 覆盖闲聊、长句、自然停顿、唤醒词打断和取消。
- 覆盖浏览器、记事本、Word、后台应用恢复和需要确认的消息草稿任务。
- 复杂任务失败必须显示具体失败步骤，不能报告伪成功。
- 全链路以同一 `turnId` 记录 KWS、VAD、ASR、DSH 接收、首 token、TTS 首音、工具执行和验证耗时。
- 输出现版本与新版本的同场景时延和成功率对比报告。

## 非目标

- 不在桌宠端复制 DSH 的会话、Agent、权限或工具系统。
- 不承诺对所有第三方软件 UI 永久免适配。
- 不把远程服务器地址、凭据、模型权重、私人音色或个人配置提交到仓库。
